4.5.1/2.4.1 packages**. The `template` verb is the authoritative schema oracle. When in doubt, run

| 19 | Compose publishes an internal dependency's port | a naive compose maps `redis: ports ["6379:6379"]` | **Publish ONLY the service you curl from the host (the mocker).** Mapping an internal dependency (Redis/RabbitMQ) to a fixed host port collides with any container already bound to it on the host: `docker compose up` aborts with `Bind for 0.0.0.0:6379 failed: port is already allocated` → the mocker container never starts → the curl gate fails. | 20 | FromFileSystem file filter | tempting to add a `Pattern:`/glob key (top level OR inside `FileSystem:`) to filter files | **The filter key is `SearchPattern` INSIDE `FileSystem:` — there is NO `Pattern` key.** `FileSystem: {Path: TestData, SearchPattern: '*.csv'}` is LAB-verified: template accepts it and at runtime only matching files load (no match -> `ERR No data found in external source for generator ... | 23 | Hermetic guards on unreachable/timed-out HTTP sessions | intuition: timed-out tx -> Outputs=0 everywhere, ExpectedCount 0 or per-source percentage works | a timed-out HTTP transaction logs `Output Source tx-N Contains 0 Outputs` BUT the session-level counter still logs `Session tx-N Outputs=1` (the failed attempt is recorded). | 24 | Consume-after-publish across sessions | intuition: put the Consumer in its own later session/stage for a clean pipeline | **Messages published to an exchange BEFORE the consumer binds are DROPPED** (no queue bound yet -> broker discards). Within ONE session, default ACTION stages solve this: Consumers=0 (bind first), Publishers=1, Transactions=2 (s02 §2.6). Put the Publisher and its Consumer in the SAME session (the s14.3 DummyApp golden shape) so the consumer queue exists before publishing; or pre-create a durable queue+binding with CreateRabbitMqQueues/CreateRabbitMqBindings at Stage 0 — but the Consumer must STILL set ExchangeName (never QueueName alone, see #28). [trial Z101] |
